5. UNCERTAINTIES & RESIDUAL RISKS
· RUM values live in one serverless instance's memory; a report and a scrape can hit different
  instances (seen on production: rum_reports absent after a 204). Fleet-wide numbers need OTLP
  metrics export or a shared store.
· /api/metrics/rum is public; bounded and validated but not rate-limited.
· Production traces need a Vercel tracing integration or OTEL_EXPORTER_OTLP_ENDPOINT; not configured.
· First production scrape after deploy showed ga_feed_up{layer="aircraft"} 0; a direct request a
  minute later returned 408 aircraft. The FeedDown alert waits 10 min for this reason.
· Mobile 60 FPS, 16 ms frame and 512 MB targets: unmeasured (no physical phone or GPU here).
· Mocked-upstream load test (scripts/perf/mock-fetch.mjs, replay only, +150 ms per upstream):
  200 concurrent, 30 s, 9 layer APIs + health -> 24,100 requests, 803 req/s, 0 errors,
  p50 219 ms, p95 257 ms, p99 457 ms, max 18.4 s; 0 requests left the machine. Single local
  process; not a 10,000-user or production result.
· 10,000-user test not run: it would load the public agencies behind each layer. Earlier local test:
  200 concurrent -> 914 req/s, p95 342 ms, 0 errors (pages + health); 50 concurrent cached layer
  API -> 1,673 req/s, p95 52 ms, 0 errors. The 50 ms API ceiling is met only for cached layers.
· npm audit reports advisories in the dependency tree; no forced fix was applied.
· No Kafka/Flink: the app is stateless serverless functions with no consumer to attach them to.
